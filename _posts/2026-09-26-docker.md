# Chapter 1. 가상화 기술과 컨테이너 가상화

> 해당 포스트는 군 복무 중 『개발자를 위한 쉬운 도커』를 읽고 학습한 내용을 개인적으로 정리한 글을 생성형 AI를 통해 1차 가공한 글입니다.

우선 Docker는 서버와 깊게 연관된 기술이기 때문에 엔터프라이즈 환경에서 서버를 운영하는 방식에 대해 먼저 소개하고 가겠습니다.

## 1. 서버 운영 방식과 가상화 기술

서버에서 소프트웨어를 실행하는 방식에는 베어메탈, 하이퍼바이저를 이용한 가상머신, 컨테이너 등이 있습니다.

### 1.1. 베어메탈(Bare Metal)

물리적인 하드웨어에 OS를 직접 설치하고, 해당 OS 위에서 소프트웨어를 실행하는 방식입니다.

```text
┌─────────────────────┐
│     Application     │
├─────────────────────┤
│     Operating OS    │
├─────────────────────┤
│       Hardware      │
└─────────────────────┘
```

### 1.2. 하이퍼바이저(Hypervisor)

하나의 물리적 시스템에서 여러 가상머신을 생성하고 관리하는 가상화 기술입니다.

하이퍼바이저는 각 가상머신에 CPU, 메모리 등의 리소스를 할당하고, 가상 하드웨어에 대한 접근을 관리하는 역할을 합니다.

하이퍼바이저는 하드웨어 위에서 직접 실행되는 방식(Type 1)과 호스트 OS 위에서 실행되는 방식(Type 2)으로 구분됩니다.

다음은 Type 1 하이퍼바이저를 기준으로 한 구조입니다.

```text
┌──────────────┬──────────────┐
│ Application  │ Application  │
├──────────────┼──────────────┤
│  Guest OS A  │  Guest OS B  │
├──────────────┴──────────────┤
│         Hypervisor          │
├─────────────────────────────┤
│          Hardware           │
└─────────────────────────────┘
```

각 가상머신에는 독립적인 게스트 OS와 커널이 존재합니다.

### 1.3. 컨테이너(Container)

컨테이너는 OS 커널의 기능을 활용하여 격리된 실행 환경을 만드는 기술입니다.

리눅스에서는 주로 **Namespaces와 Cgroups**를 활용합니다.

- **Namespaces:** 프로세스, 파일시스템의 마운트 환경, 네트워크 등의 시스템 자원을 격리합니다.
- **Cgroups:** CPU, 메모리 등의 리소스 사용량을 제한하고 관리합니다.

LXC(Linux Containers)는 이러한 리눅스 커널 기능을 활용하는 대표적인 컨테이너 기술 중 하나입니다.

```text
┌──────────────┬──────────────┐
│ Container A  │ Container B  │
│              │              │
│ Application  │ Application  │
│ Libraries    │ Libraries    │
├──────────────┴──────────────┤
│         Host Kernel         │
├─────────────────────────────┤
│          Hardware           │
└─────────────────────────────┘
```

컨테이너마다 별도의 커널이 존재하는 것이 아니라, 여러 컨테이너가 하나의 호스트 커널을 공유하는 구조입니다.

## 2. 하이퍼바이저와 컨테이너의 차이

하이퍼바이저와 컨테이너의 공통점은 모두 **격리된 가상화 환경을 제공한다**는 것입니다.

차이점으로는 하이퍼바이저 기반 가상머신에는 게스트 OS와 호스트 OS의 커널이 독립적으로 존재할 수 있지만, 컨테이너는 호스트 커널을 공유한다는 점이 있습니다.

가상머신의 경우 애플리케이션에서 발생한 시스템 콜(System Call)은 게스트 OS의 커널에서 처리됩니다. 이때 가상 하드웨어 접근과 같은 일부 작업에는 하이퍼바이저의 개입이 필요할 수 있습니다.

반면 컨테이너는 호스트 커널을 공유하기 때문에 애플리케이션에서 발생한 시스템 콜을 호스트 커널에서 직접 처리합니다.

```text
[ Virtual Machine ]

Application
     │
     ▼
Guest OS Kernel
     │
     ▼
Virtual Hardware
     │
     ▼
Physical Hardware


[ Container ]

Application
     │
     ▼
Host OS Kernel
     │
     ▼
Physical Hardware
```

위 구조는 개념적으로 단순화한 것으로, 가상머신의 모든 시스템 콜이 하이퍼바이저를 거치는 것은 아닙니다.

결과적으로 컨테이너는 별도의 게스트 OS를 실행하지 않기 때문에 가상머신에 비해 일반적으로 리소스 사용량이 적고 실행 준비 시간이 빠르다는 이점을 가집니다.

**Docker는 이러한 컨테이너 가상화 기술을 쉽게 사용할 수 있도록 하는 플랫폼**이라고 보면 됩니다.

## 3. Docker의 동작 구조

Docker는 **클라이언트-서버(Client-Server) 모델**을 기반으로 합니다.

Docker는 사용자의 명령을 전달하는 Docker Client와 컨테이너를 관리하는 Docker Daemon으로 구성됩니다.

```text
┌─────────────────┐
│      User       │
└────────┬────────┘
         │ CLI Command
         ▼
┌─────────────────┐
│  Docker Client  │
└────────┬────────┘
         │ API Request
         ▼
┌─────────────────┐
│  Docker Daemon  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   Containers    │
└─────────────────┘
```

클라이언트가 Docker 관련 명령어를 CLI로 실행하면 사용자의 명령을 API 요청으로 변환하여 Docker Daemon에 전달합니다.

Docker Daemon은 해당 요청에 따라 컨테이너를 생성하거나 관리하는 등의 작업을 수행하고, 그 결과를 클라이언트에 전달합니다.

CLI를 사용하는 이유는 Docker Daemon의 API에 직접 요청을 보내는 과정이 복잡하기 때문에, 사용자가 간단한 명령어만으로 API를 호출할 수 있도록 하기 위해서입니다.

## 4. Docker CLI 기본 명령어

```bash
docker --help
```

Docker 명령어에 대한 도움말을 확인할 수 있습니다.

Docker 명령어는 주로 다음과 같은 형식을 취합니다.

```bash
docker [Management Command] [Command]
```

대분류에 해당하는 Management Command는 관리할 대상을 나타내며, 일부 명령어에서는 생략할 수 있습니다.

예를 들어 컨테이너 실행 및 삭제 명령어는 다음과 같습니다.

```bash
# 컨테이너 생성 및 실행
docker run [옵션] 이미지명

# 컨테이너 삭제
docker rm 컨테이너명/ID
```

위 명령어는 Management Command를 명시하여 다음과 같이 작성할 수도 있습니다.

```bash
# 컨테이너 생성 및 실행
docker container run [옵션] 이미지명

# 컨테이너 삭제
docker container rm 컨테이너명/ID
```

즉, `docker run`과 `docker container run`은 동일한 명령어이며, `docker rm`과 `docker container rm` 역시 동일한 명령어입니다.

## 정리

| 구분 | 특징 |
|---|---|
| 베어메탈 | 물리적 하드웨어에 OS를 직접 설치 |
| 하이퍼바이저 | 가상머신마다 독립적인 게스트 OS와 커널 사용 |
| 컨테이너 | 호스트 커널을 공유하면서 실행 환경 격리 |
| Docker | 컨테이너 생성 및 관리를 위한 플랫폼 |
| Docker Client | CLI 명령을 API 요청으로 변환 및 전달 |
| Docker Daemon | API 요청에 따라 컨테이너 관리 작업 수행 |
