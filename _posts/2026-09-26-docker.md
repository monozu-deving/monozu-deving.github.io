# Chapter 1. 가상화 기술과 컨테이너 가상화

> 해당 포스트는 군 복무 중 『개발자를 위한 쉬운 도커』를 읽고 학습한 내용을 개인적으로 정리한 글을 생성형 AI를 통해 1차 가공한 글입니다.

Docker는 서버 운영과 밀접한 관련이 있는 기술입니다. 따라서 Docker를 알아보기 전에 서버 운영 환경에서 사용되는 몇 가지 방식을 먼저 살펴보겠습니다.

## 1. 서버 운영 방식과 가상화 기술

서버에서 소프트웨어를 실행하는 방식에는 베어메탈, 하이퍼바이저를 이용한 가상머신, 컨테이너 등이 있습니다.

- **베어메탈(Bare Metal):** 물리적인 하드웨어에 OS를 직접 설치하고, 해당 OS 위에서 소프트웨어를 실행하는 환경입니다.
- **하이퍼바이저(Hypervisor):** 하나의 물리적 시스템에서 여러 가상머신을 생성하고 관리하는 가상화 기술입니다. 각 가상머신에 CPU, 메모리 등의 자원을 할당하고 가상 하드웨어에 대한 접근을 관리합니다. 하이퍼바이저는 하드웨어 위에서 직접 실행되거나 호스트 OS 위에서 실행될 수 있습니다.
- **컨테이너(Container):** OS 커널의 기능을 활용하여 격리된 실행 환경을 만드는 기술입니다. 리눅스에서는 주로 Namespaces와 Cgroups를 활용하여 프로세스, 파일시스템, 네트워크 환경을 격리하고 자원 사용량을 관리합니다. LXC(Linux Containers)는 이러한 커널 기능을 활용하는 대표적인 컨테이너 기술 중 하나입니다.

### 1.1. 하이퍼바이저와 컨테이너의 차이

하이퍼바이저 기반 가상머신과 컨테이너는 모두 **격리된 실행 환경을 제공한다**는 공통점이 있습니다.

그러나 두 기술은 커널을 사용하는 방식에서 차이가 있습니다.

**하이퍼바이저 기반 가상머신**은 각각 독립적인 게스트 OS와 커널을 가집니다. 따라서 하나의 물리적 서버에서도 서로 다른 운영체제를 실행할 수 있습니다.

반면 **컨테이너**는 별도의 게스트 커널을 실행하지 않고 호스트 OS의 커널을 공유합니다.

이러한 차이는 시스템 콜(System Call)을 처리하는 방식과 자원 사용량에도 영향을 미칩니다.

가상머신 내부의 애플리케이션은 게스트 OS의 커널에 시스템 콜을 요청합니다. 일반적인 시스템 콜은 게스트 커널에서 처리되지만, 가상 하드웨어 접근 등 일부 작업에는 하이퍼바이저의 개입이 필요할 수 있습니다.

반면 컨테이너 내부의 애플리케이션은 호스트 커널에 직접 시스템 콜을 요청합니다.

따라서 컨테이너는 별도의 게스트 OS를 실행할 필요가 없어 일반적으로 가상머신보다 자원 사용량이 적고 실행 준비 시간이 짧다는 장점이 있습니다.

결과적으로 **Docker는 이러한 컨테이너 기술을 쉽게 생성하고 실행하며 관리할 수 있도록 지원하는 플랫폼**이라고 볼 수 있습니다.

## 2. Docker의 동작 구조

Docker는 **클라이언트-서버(Client-Server) 모델**을 기반으로 동작합니다.

주요 구성 요소는 사용자의 명령을 전달하는 **Docker Client**와 컨테이너를 관리하는 **Docker Daemon**입니다.

사용자가 CLI(Command Line Interface)를 통해 Docker 명령어를 입력하면 다음과 같은 과정이 진행됩니다.

1. 사용자가 Docker CLI에 명령어를 입력합니다.
2. Docker Client는 해당 명령을 Docker API 요청으로 변환합니다.
3. Docker Daemon은 전달받은 API 요청에 따라 컨테이너를 생성하거나 관리하는 등의 작업을 수행합니다.
4. 작업 결과가 Docker Client로 전달되고 CLI에 표시됩니다.

CLI를 사용하는 이유는 사용자가 Docker Daemon의 API를 직접 호출하지 않고도 간단한 명령어를 통해 Docker의 기능을 사용할 수 있도록 하기 위해서입니다.

즉, **Docker Client는 사용자의 명령을 전달하는 역할을 하고, Docker Daemon은 실제 작업을 수행하는 역할**을 합니다.

## 3. Docker CLI 기본 명령어

Docker CLI에서 사용할 수 있는 명령어는 다음과 같이 확인할 수 있습니다.

```bash
docker --help
```

Docker 명령어는 일반적으로 다음과 같은 구조를 가집니다.

```bash
docker [Management Command] [Command]
```

여기서 Management Command는 관리할 대상을 나타내며, Command는 해당 대상에 수행할 작업을 의미합니다.

일부 명령어는 Management Command를 생략한 축약형으로도 사용할 수 있습니다.

예를 들어 컨테이너를 실행하거나 삭제할 때 다음과 같은 명령어를 사용합니다.

```bash
# 이미지를 기반으로 컨테이너 생성 및 실행
docker run [옵션] 이미지명

# 컨테이너 삭제
docker rm 컨테이너명/ID
```

위 명령어는 다음과 같이 Management Command를 명시하여 작성할 수도 있습니다.

```bash
# 컨테이너 생성 및 실행
docker container run [옵션] 이미지명

# 컨테이너 삭제
docker container rm 컨테이너명/ID
```

따라서 `docker run`과 `docker container run`은 동일한 기능을 수행하며, `docker rm`과 `docker container rm` 역시 동일한 기능을 수행합니다.

## 정리

- **베어메탈:** 물리적 하드웨어에 OS를 직접 설치하는 환경
- **하이퍼바이저:** 독립적인 게스트 OS를 실행하는 가상머신을 생성하고 관리하는 기술
- **컨테이너:** 호스트 커널을 공유하면서 격리된 실행 환경을 제공하는 기술
- **Docker:** 컨테이너를 쉽게 생성하고 실행 및 관리할 수 있도록 지원하는 플랫폼
- **Docker Client:** 사용자의 명령을 API 요청으로 변환하여 전달
- **Docker Daemon:** API 요청을 받아 실제 컨테이너 관리 작업을 수행
